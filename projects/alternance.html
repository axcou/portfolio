Alternance - Salvia Développement

Python SQL Server Data Engineering Entrepôt de données Fév. 2026 - Sept. 2027

Contexte

Salvia Développement est un éditeur de logiciels métiers pour le logement social. J'interviens au sein du pôle Finance, sous la direction de Gaël Gerard (Référent Technique Gamme Finance) et de Wanig Guillo (Chef Data du groupe), sur la construction d'un entrepôt de données centralisant deux systèmes aux logiques métier distinctes, jusqu'ici non consolidés : une solution de gestion des financements et une solution de gestion du patrimoine immobilier.

Traiter des données à des fins décisionnelles

Outils : Python (PyYAML, json, xml.etree, python-docx), SQL Server, optimisation de requêtes (tables temporaires, caches, index)

  • Développement d'un script Python de détection automatique de clés de jointure entre deux bases SQL Server contenant chacune plusieurs centaines de colonnes. Le défi principal était l'explosion combinatoire : un filtrage préalable par types de données, combiné à des caches de valeurs distinctes et des requêtes optimisées, a ramené le traitement de plusieurs jours à quelques minutes.
  • Développement de deux scripts de transformation documentaire (YAML/JSON et XML vers tableaux Word structurés via python-docx) pour rendre les données des contrats API accessibles aux équipes métier sans passer par les développeurs.
  • Acquis : optimisation de requêtes SQL en contexte de production, manipulation de structures de données hétérogènes, automatisation de traitements à forte valeur ajoutée.

Recul : le premier script fonctionnait mais n'était pas robuste aux cas particuliers. Confronté à des fichiers sources variables en production, j'ai dû reprendre la logique de parsing entièrement pour gérer les structures imbriquées. Ce cycle m'a appris qu'un traitement de données "qui marche sur l'exemple" n'est pas un traitement de données fiable.

Analyser statistiquement les données

Outils : Python, SQL Server, scoring de similarité par valeurs communes

  • Mise en place d'un scoring quantitatif basé sur le taux de valeurs communes entre colonnes, avec des seuils de filtrage pour écarter les colonnes trop pauvres sémantiquement. L'analyse a produit un classement des paires candidates, dont la plus prometteuse atteint un taux de correspondance très élevé.
  • Acquis : construction d'un indicateur de similarité, arbitrage entre couverture statistique et pertinence sémantique, lecture critique des résultats produits.

Recul : c'est la compétence la moins directement mobilisée dans mon alternance. L'identification de clés de jointure relève davantage de l'ingénierie des données que de l'analyse statistique au sens strict. Un fort taux de correspondance est encourageant, mais il ne garantit pas que les valeurs partagées correspondent aux mêmes entités métier : la validation sémantique reste une étape humaine irremplaçable.

Valoriser une production dans un contexte professionnel

Outils : Python (python-docx), réunions parties prenantes, livrables Word et Excel

  • Organisation et animation de réunions avec le référent technique, la cheffe de marché Patrimoine et le directeur commercial pour recueillir les besoins autour de l'entrepôt. Ces échanges ont produit une synthèse d'architecture couvrant le modèle en étoile, les enjeux de traçabilité, la gestion RGPD et la normalisation des référentiels.
  • Les outils de transformation documentaire ont eu un impact direct sur les équipes : les contrats API sont désormais lisibles sans passer par les développeurs.
  • Acquis : interface technique/métier, conduite de réunions avec des interlocuteurs de niveaux variés (technique, produit, commercial), production de livrables structurés et réutilisables.

Recul : au début, mes synthèses étaient trop techniques pour être utilisables par les équipes produit. J'ai appris à séparer les enjeux fonctionnels des détails d'implémentation, et à adapter le niveau d'abstraction selon l'interlocuteur, un réflexe qui ne s'acquiert qu'en situation réelle.

Modéliser les données dans un cadre statistique

Outils : conception star schema, modélisation multi-tenant, Python, SQL Server

  • Conception d'une architecture en étoile (tables de faits / tables de dimensions) pour l'entrepôt de données Finance et Maîtrise d'Ouvrage, adaptée aux usages analytiques ciblés : comparaisons inter-organismes, suivi temporel, indicateurs sectoriels.
  • La contrainte multi-tenant (isolation des données par client tout en mutualisant l'infrastructure) a nécessité une réflexion sur l'architecture au-delà du schéma relationnel classique, en intégrant les enjeux RGPD dès la conception.
  • Acquis : modélisation décisionnelle (star schema), articulation entre besoins métier et contraintes techniques, sensibilisation aux enjeux de gouvernance et de conformité des données.

Recul : la modélisation dans mon alternance est orientée data engineering plutôt que modélisation statistique au sens académique. Je n'ai pas encore déployé de modèles prédictifs en production : l'entrepôt que je construis est le socle qui rendra ces analyses possibles, mais ce pas reste à franchir. C'est un point à consolider dans la suite de l'alternance.

Bilan

Cette alternance m'expose à des dimensions que la formation seule ne peut reproduire : la complexité des systèmes d'information réels, les contraintes de maintenabilité et de fiabilité en production, et la nécessité de justifier chaque choix technique devant une équipe. La prise de conscience la plus forte : la valeur d'une donnée dépend avant tout de sa capacité à être documentée et comprise, sans quoi elle reste techniquement disponible mais pratiquement inutilisable. Les compétences acquises hors formation (Git, Docker, CI/CD, gestion de projet) commencent à dessiner le profil d'ingénierie que je veux construire.
