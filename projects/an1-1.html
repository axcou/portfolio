SAÉ 1.01 - Reporting à partir de données stockées dans un SGBD relationnel

SQL Python Excel Reporting

Objectif

À partir d'une base de données SQL sur les catastrophes climatiques (feux, inondations, etc.), rédiger une documentation d'installation de PostgreSQL et d'initialisation des tables, réaliser deux visualisations guidées et une libre, puis rassembler le tout dans un rapport de 6 pages. Les visualisations ont été produites avec Metabase.

Ce que j'ai fait

  • Rédaction de la documentation d'installation de PostgreSQL, d'exécution du script de création de la base et de mise en place de Metabase
  • Réalisation de deux visualisations guidées : nombre total de catastrophes par année, et nombre de chaque type de catastrophe par année
  • Conception d'une visualisation libre : carte choroplèthe mondiale du nombre d'inondations par pays, via une requête SQL personnalisée avec double JOIN (country + disaster) et GROUP BY
  • Rédaction d'un rapport de 6 pages structuré en deux parties : environnement technique (installation) et travail exploratoire (graphiques)

Résultat obtenu

  • Une carte choroplèthe mondiale affichant la répartition des inondations par pays (dégradé de couleur via le code ISO2)
  • Deux graphiques guidés illustrant l'évolution temporelle et la répartition par type des catastrophes climatiques
  • Un rapport de 6 pages documentant l'environnement de travail et les analyses produites

Compétences mobilisées

  • SQL : jointures multiples, agrégations (COUNT, GROUP BY), filtrage (WHERE), utilisation d'alias pour la lisibilité
  • Création de visualisations dans Metabase : histogrammes et carte choroplèthe
  • Rédaction de documentation technique (installation, exécution de scripts SQL)
  • Structuration d'un rapport analytique en séparant partie technique et partie analytique

Difficultés rencontrées

  • Rendre la requête SQL lisible et bien structurée : choisir des alias explicites (country_iso, disaster_nom, disaster_compte), organiser les JOIN dans un ordre logique et produire un code compréhensible à la relecture
  • Construire la structure du rapport de façon cohérente : séparer installation et analyse sans rendre la lecture fragmentée

Ce que j'en retiens

Metabase et SQL sont des outils qui ont directement resurgi dans d'autres SAÉ (notamment la 2.01). Cette SAÉ m'a surtout appris qu'une visualisation pertinente se réfléchit avant de se coder : choisir une carte choroplèthe pour les inondations par pays, c'est un choix de fond qui conditionne toute la lisibilité du résultat - et y passer du temps vaut le coup.
